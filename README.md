# 2.6候选版：分类编号多选

在分类编号处输入 `2,5,6,19` 或 `5-8`，编号以当次屏幕分类表为准。
按选择顺序逐个分类选卷，每类选好输入 `s` 进入下一类；最后一类输入 `s` 才开始全部采集。
支持按卷编号/范围、跨页选择，所选卷统一保存并按分类与页码恢复；单分类用法不变。
Windows构建运行全套测试、EXE帮助和内置浏览器启动检查。真实跨分类账号运行仍需独立验收，不能用模拟测试代替。
此版本保持原始题位与来源占位内容，不凭空补题；导出后应标记来源缺题，不把默认A当真实标准答案。
输出仍为采集原始数据、V2和媒体文件；历史网站导入器需要格式适配。

## 最短使用步骤

1. 完整解压Windows包，保留`_internal`，双击`FenbiCollector.exe`。
2. 在弹出的粉笔浏览器中正常登录，回控制台按Enter。
3. 默认Enter进入选卷，选择“江苏”分类，输入`ab`选择本页五组A/B十套，再输入`s`开始。
4. 结果看`fenbi_output/batch_summary.txt`。成功卷对应目录有`paper_v2.json`；缺项卷不会生成成功回执。
5. 中途关闭后重启，保留原`fenbi_output`；若检测到未完成任务，默认Enter续跑，也可输入`5`。成功文件核验通过后跳过，只处理剩余卷。

普通故障限次重试后仍不能解决的卷会留在待补清单；登录/验证码会暂停提示，完成后自动继续。等待默认15分钟，超时保留任务。不会代填凭据或解决验证码，不重复点击状态不明的交卷。占位交卷可能影响粉笔自身的历史/预测分，不作为个人真实学习成绩。

`ab`在当前真实江苏列表已读出2021—2025的五组A/B十套。若本页不足五组唯一A/B，可用`n`翻页或输入编号/范围逐页选卷。程序按标题和列表签名核对，列表变化时保留失败，不点击其他卷。

## 当前改动

- 从原列表的真实试卷条目打开试卷，保留标签页中的分类与登录状态，不再新开空白页重建分类。
- 同页打开试卷后，返回并核对原列表、分类、页码；弹窗打开时保留原列表窗口。
- 列表状态无法恢复时停止整个批量任务，保存 `listing_failure.json` 和本地截图，避免逐卷重复相同错误。
- 查询下一题/下一页使用可见 DOM 按钮，单步限时六秒；按钮有歧义时保留错误。
- 采集每轮输出已读取题数，阶段限时约九十秒，超时保留数据并标记待补。
- 进入采集流程前写入检查点；每轮更新，保存正常渲染的题目片段。
- 合格卷才生成 `paper_v2.json`；缺项、来源题数未知或资源未核验的卷不计入五套。
- 自动交卷为占位提交，单独记录，不作为个人学习成绩。自动无法识别确认窗时保留手动处理入口。

## 开发运行

使用 Python 3.10 或更新版本：

```sh
python -m pip install -r requirements.txt
python -m playwright install chromium
python standalone_main.py
```

原有 CLI 参数可用：`--plan` 明确当天目标，`--daily-target 5` 指定数量，`--no-auto-submit` 关闭自动交卷。计划条目为正常页面的 `url`、完整 `title`、经核实的 `expected_count`，不得猜接口或统一套用题量。

## 输出与诊断

输出在 `fenbi_output/`：启动状态、`capture_checkpoint.json`、逐卷工作数据、V2、audit/missing/media 报告和每日结果。批量列表错误会自动保存 `listing_failure.json` 及本地截图；这些诊断不会自动上传。检查点属于中间数据，不能直接算作完整卷。正常渲染题目资源与平台统计保留来源，不推理补出官方答案。

`fenbi_browser_profile/` 是本机登录目录，不得上传或共享。题库、学习记录、账号资料和真实页面抓取文件均不应提交到本仓库；测试只有原创合成内容。
