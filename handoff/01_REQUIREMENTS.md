# 任务要求与完成标准

## 用户直接明确的目标

- 每天获取五套卷子，用于本人日常学习，包含 A/B 卷。
- 帮忙改代码、实际执行、测试验证，尽量让 AI 完成技术操作。
- 用户使用 Windows；已经下载并运行 GitHub 构建的 2.3 EXE。
- 用户已授权实际采集与程序上传构建。
- 当前请求：把全部代码进度、要求、已有成果、已做工作、任务方法整理打包，让下一位 AI 立即接手并验证。

当前代码把五套理解为五份有独立身份的完整卷，A/B 分别保存、分别计数；没有证据支持把“含 A/B”扩写为“每天五对、十份”。

## 从用户历史交接资料继承的产品目标

个人江苏省考学习题库：原卷顺序作答，以及按年度、卷别、科目、题型、考点、材料组、平台正确率筛选。长期扩展近十年国考、江苏和其他重点省份；当前优先任务仍是把每天五卷的真实流水线跑通。

旧资料首批目标是 2022—2026 年五类卷，共 25 个目标位：国考行政执法、国考市地、江苏 B、浙江 A、浙江 B。目标位不等于已取得成品。历史更大目标清单不表示已经收齐。

## 每卷必须保留

- 完整考试身份、年份、地区、科目、A/B 等卷别、网友回忆版等版本标签、完整标题、原始页面 URL、取得时间与来源证据。
- 官方/平台实际提供的题干、四个选项、答案、解析、原始题目 ID、可核实的题序和材料关联。
- 图片、表格、公式原始 HTML 及资源地址或既有内嵌图片；真实来源的正确率等统计。
- 原始文件、渲染片段或正常导出，SHA-256、完整性报告、缺失清单、媒体核验与阶段计时。

不编造答案、ID、题数、题序、图片地址或平台统计。缺字段填 null 或明确待补。不能用用户占位提交的成绩代替学习能力或平台正确率。单题“来源”可能指另一卷，不能据此改变当前卷归属。

## 当前网站 V2

顶层固定为 `name / question_count / card / materials / questions`。

题目保留 `id, globalId, subject, path, tags, year, order, stemHtml, optionsHtml, answer, explanationHtml, source, demo, rate, rateSource, totalCount, mostWrong`。

材料位于顶层 `materials[{globalId, content}]`；题卡节点通过 `key` 对应题目 `globalId`，通过 `materialKeys` 对应材料。`local-material:` 前缀明确表示本地派生材料 ID，不冒充平台原 ID。不能跨卷按“第 35 题”合并答案；按原 ID 对齐，按卷内题序排序。

当前旧网站验证记录表明：逐卷导入；不能假设支持旧的多卷 `paperMemberships`；题目可能按卷命名空间保存。SVG/MathML 清理行为需要实际验证，不能直接承诺兼容。

## 完整卷与每日五卷的验收

1. 总题数必须有独立、可核对的原卷或答题卡证据；不能取“已收集题数”作为预期题数。不可把其他年份的 130 或当前看到的 135 硬编码进去。
2. 题号连续，卷内原始 ID 唯一，题卡与题目一一对应，材料引用完整，答案解析齐全，媒体实际可用。缺项保存待补，不计完整。
3. 保留 A/B 身份；同一卷别名 URL 不重复计数。五份完整卷才算当天达标；题位和跨卷唯一题数分别报告。
4. 在用户当前网站独立测试环境逐卷导入，再导出复核实际保存的题序、材料、图片、答案与统计。成功弹窗不代替导出复核。
5. 真实账号连续五卷和多日稳定性未完成之前，不能宣称实现“稳定每天五套”。

## 资料处理边界

正常有权访问的文件、页面和导出优先。未知接口、隐藏状态、验证码绕过、付费或访问限制绕过不属于既有授权。密码、验证码、Cookies、浏览器登录目录不进入交接包，也不公开上传。
