# 文件、访问与包的范围

## 可从 GitHub 下载的代码交接包

- `code/`：当前仓库全部已跟踪文件，含源码、测试、CI、报告与本交接说明。
- `history/repository.bundle`：完整 Git 历史，不包含 Git 配置文件、HTTP 认证配置或浏览器登录目录。
- `history/COMMITS.txt`：提交清单。
- 根目录 `START_HERE.md` 和 `NEXT_AI_PROMPT.txt`：接手入口。
- `MANIFEST.json`：逐文件字节数与 SHA-256；清单自身不列入自身哈希。
- 使用 `python code/handoff/verify_package.py 交接包.zip` 验证 ZIP、文件清单和全部哈希。

代码包没有旧题库原文、原始试卷、真实页面 DOM、图片缓存、平台登录态，也没有 381 MB 的 Windows EXE/browser 工件；EXE 在已验证构建的下载页，需要时下载或重建。

## 本地完整资料包（不公开上传）

在代码交接内容之外还包含：

1. `03_已有关键成果/`：旧的可导入两卷 V2、历史实际导入报告、目标/步骤说明及转换工具。
2. `04_原始附件/`：用户上传的原 Markdown、采集器原 ZIP、四卷原始交接 ZIP；保留原名并校验哈希。
3. `05_早期代码与修复证据/`：原程序审查目录、早期 fixed/windows_easy/paste/progress 候选、补丁工具与传输修复记录。旧代码仅供追溯，不是最新入口。
4. `06_环境与旧资料校验/`：依赖版本、旧 445 文件 manifest 核验结果、当前本地包核验结果。

四卷原交接包含重建出的 445 份旧资料以及嵌套的历史代码、网站版本、工作库、图片与媒体报告。没有再次复制整个 132 MB 解压树以避免重复膨胀；需深入旧历史时解压四卷。最初提及的单文件大交接 ZIP 没有本地二进制副本，四卷是后续提供并已用于重建的替代资料，不能声称保留了该单包原始字节。

对本地完整资料包也生成逐文件清单、SHA-256、ZIP CRC 与实际哈希核验。它只在工作区保存，不经公开 GitHub 分发；下一位 AI 若只拿到代码包，不应声称已经持有其中的旧题库或用户电脑上的新采集文件。

## 从 Git bundle 恢复

在一个空目录中：

```sh
git init restored
git -C restored fetch /实际路径/history/repository.bundle HEAD:refs/heads/main
git -C restored switch main
```

包内 `code/` 已可直接运行，无需先恢复 Git 历史。恢复前可在任意 Git 仓库中执行 `git bundle verify 路径`。

## 授权与协作注意

用户要求 AI 承担技术排查，不要无故重复请求已经给出的程序修复、正常采集或程序推送授权。新的外部私有资料公开、删除个人题库、分享凭据不属于这次授权。

历史文档可能含先前窗口的方案和限制，先分清它们是背景资料还是用户当前请求。不要把旧目标、旧测试和旧页面版本自动当成当前已完成工作。
