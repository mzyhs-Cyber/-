# 三科20题离线组卷实验

独立的元数据规则原型，固定言语8、判断7、资料5。未接入生产应用、浏览器数据库、笔迹或发布接口。不得把此原型当成已上线的训练系统。

## 运行

Node 22以上，无依赖、无网络请求：

```sh
cd offline20
node --test test/*.test.mjs
```

32项隔离检查覆盖固定题数、完整材料、训练反馈3倍权重及正确反馈降权、排除题仍查重、最新复盘版本撤回、猜对不解除、跨卷别名、近期窗口、难度范围、候选质量、取消、并发计划冻结、跨日和账号隔离。存储使用注入的模拟适配器，未实现真实IndexedDB事务或实机恢复。

## 模式

`strict`只允许已核验答案、已确认离线资源完整的元数据进入正式计划。`metadata-preview`仅做题数和规则可行性实验，绕过这两个门槛，但始终返回`canStart:false`，不得启动或上传训练。

`adapt.py`可处理当前授权的本地备份及分页复盘样本，生成`private/metadata.json`；`experiment.mjs`用该文件测量。私密输入和生成清单不随代码提供、不应提交。适配器当前不从平台的“内容完整”推断独立核验完成，平台正确率只作为难度代理。

## 已知限制

1. 依赖已有细分类；没有语义分析，不识别自由文本错因，不声称微观机制已核验。
2. 候选按形状保留有限数量，并使用有界搜索。返回`searchLimited:true`时未证明全局最优；找不到时只能报告搜索预算或资源缺口，不能据此证明题库无解。
3. 同类题最多4题；完整材料可能超过用途比例，但保留整组并记录例外。一般保持槽位按模块约三分之一，在可用候选无法满足时记录例外。
4. 历史去重覆盖仅限已输入的记录，不包含未同步设备；不支持全账号离线一致性。
5. 单次原题重做只算一个独立样本；尚未实现更复杂的长期保持模型。
6. 尚无UI、真实本地持久化、跨标签页事务和图片缓存检查；`PlanManager`只定义适配器契约。没有生产部署或iPad验收。
7. 即使索引和选题分批让出事件循环，仍须在目标设备测量；Node时延不能换算成iPad时延。

## 实验目的

验证规则能否执行，并定位真实题库的字段缺口。规则测试通过不证明选题具有教学效果，不证明实际设备零卡顿。下一步应为已支持的细型建立可用候选池、补齐离线媒体检查，再接入预览界面。
